## Connecting with the Provider

- Open the Discord server where you want to create the webhook.
- Click on the settings icon next to the server name, and select "Server Settings."
- In the left-hand menu, click on "Integrations," and then click on "Webhooks."
- Click the "Create Webhook" button, and give your webhook a name.

## Message Parameters

Any parameter accepted by the [Discord Execute Webhook API](https://discord.com/developers/docs/resources/webhook#execute-webhook-jsonform-params) can be passed as a workflow `with:` key.

| Parameter | Type | Description |
|---|---|---|
| `content` | string | Message text (up to 2000 characters) |
| `embeds` | list | Up to 10 rich embed objects |
| `components` | list | Interactive components (buttons, action rows) |
| `username` | string | Override the webhook default username |
| `avatar_url` | string | Override the webhook default avatar |
| `allowed_mentions` | object | Control which mentions trigger notifications |
| `files` | list | List of file specs for attachment uploads (see below), up to 10 |
| `poll` | object | A poll object |
| `thread_name` | string | Create a thread in a forum/media channel |
| `applied_tags` | list | Tag IDs to apply to forum thread |
| `flags` | integer | Message flags (e.g., suppress embeds) |
| `message_id` | string | Id of a previously sent message - edits it instead of posting a new one (see below) |
| `wait` | boolean | Query param: wait for message confirmation and get the message id back |
| `thread_id` | snowflake | Query param: send to existing thread |
| `with_components` | boolean | Query param: enable interactive components for non-app-owned webhooks |

`tts` is explicitly **not** supported and is dropped (with a warning logged) rather than forwarded - see the provider README for rationale.

At least one of `content`, `embeds`, `components`, `files`, or `poll` is required when sending a new message (not required when editing via `message_id`). Discord's hard limits are enforced client-side with a clear error: content up to 2000 characters, up to 10 embeds, up to 10 files (10 MiB each, Discord's default per-file limit).

### File Attachments

The `files` parameter accepts a list where each element can be:

- **Dict**: `{base64: "...", filename: "chart.png"}` - the way to attach a file generated by an earlier workflow step (e.g. a rendered chart, a log excerpt), referenced via `{{ steps.<name>.results.<key> }}`
- **Raw bytes** or **tuple** `(filename, content_bytes, content_type)`: programmatic use only, not expressible in workflow YAML

There is deliberately no "file path" form. This provider runs in the same shared, long-running process as every other tenant's workflows, so a path parameter driven by workflow templating (which can embed alert/event data) would let a workflow read arbitrary files from the server's filesystem. Base64 keeps the file entirely in-memory and flows through Keep's existing step-output/templating mechanism.

Multiple files are uploaded as `files[0]`, `files[1]`, etc.

### Editing Messages

Discord webhooks can edit messages they previously sent, without any additional authentication. Send a message with `wait: true` to get its id back (`result["message_id"]`), then reuse that id in a later step:

```yaml
actions:
  - name: discord-notify
    provider:
      type: discord
      config: "{{ providers.mydiscord }}"
      with:
        content: "Investigating high CPU on web-01..."
        wait: true # required to receive the message id back

  - name: discord-resolve
    provider:
      type: discord
      config: "{{ providers.mydiscord }}"
      with:
        message_id: "{{ steps.discord-notify.results.message_id }}"
        content: "Resolved: CPU back to normal."
```

### Rate Limiting

Discord webhooks are rate limited. If a `429` response is received, the provider automatically retries (up to 3 attempts total), honoring the `Retry-After` delay Discord reports, capped at 30 seconds per wait.

### Validating the Webhook

When the provider is configured, Keep validates that the webhook URL is a genuine `discord.com`/`discordapp.com` webhook and reachable via a `GET` request (Discord's "Get Webhook with Token" endpoint) - no message is sent during validation. URLs on other hosts are rejected at configuration time.

### Example: Rich Embed

```yaml
actions:
  - name: discord
    provider:
      type: discord
      config: "{{ providers.mydiscord }}"
      with:
        content: "Alert fired!"
        username: "Keep AlertBot"
        embeds:
          - title: "CPU above threshold"
            description: "Server web-01 is at 92% CPU"
            color: 16711680
```
